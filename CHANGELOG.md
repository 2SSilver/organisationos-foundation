# Foundation CHANGELOG

This is the announcement surface for merged substrate changes — glossary, standard, template, or interface clarifications that do not rise to the level of a CDR. Each merged change gets one dated, one-line entry, added as part of the same PR that makes the change.

`find-relevant-knowledge` surfaces the most recent entries here, so an operator whose session started before a merge still sees what changed.

## Entries

- 2026-09-15 — Three findings that broke a fresh adopter on day one. `format-gate`'s extension parser derived `ext="${f##*.}"`, so `settings.local.json.example-admin` resolved to the extension `example-admin` and the gate failed on every PR touching any of the eight settings-example files across the three repos — six in Foundation, one each in Leadership and Domain, not the six in one repo previously recorded. The scan now lives in `.github/scripts/format-scan.sh` with a fixture suite over the six distinct basenames the eight real files reduce to — Leadership's and Domain's `.claude/settings.local.json.example` share Foundation's basename, and the scan keys on basename, so the six cover all eight — run on every Foundation PR; `format-gate.yml` gained `foundation-repo` and `foundation-ref` inputs so callers can resolve it: `foundation-ref` follows the same shape `banned-string-check.yml` uses, while `foundation-repo` stays optional with an owner-derived default rather than `banned-string-check.yml`'s required-with-no-default. `allowed_extensions` deliberately stays in the workflow: moving it into the script would leave the FORMATS.md drift check with nothing to compare. `docs/setup-org.md` Step 5 now creates the `v1` tag before Actions are enabled — `gh repo create --template` copies no tags, so all 21 callers failed on their first run against a documented setup that never created it — and Step 3 now names the two supply-chain placeholders its sweep never matched. A new Step 10 runs `.github/scripts/setup-check.sh`, which verifies all four conditions in the adopter's own clone. Closes N1, N2 and N5. (@2SSilver)
- 2026-09-14 — `banned-string-check` now implements the pattern language `banned-patterns.yml` declares. The `!context-near` co-occurrence directive had never run: the scan extracted `.pattern` keys only, so an entry without one was filtered out before the scan began — and `coverage-gaps.md` names that directive as the sole defence for co-occurrence identifiers. Declared `match:` modifiers were never read either, and a multi-word pattern was split on whitespace into separate patterns, so `"Jane Smith"` matched any `Jane` and any `Smith`. The scan now lives in one script both the CI gate and the pre-commit hook call, so the two cannot drift; `match:` is gone from the pattern file in favour of stating what the scan always applies; `banned-patterns-validate` compile-checks every pattern rather than only those flagged `regex`; and `.github/scripts/banned-scan.test.sh` runs on every Foundation PR. Closes N7 and N8. (@2SSilver)
- 2026-09-14 — `standards/templates/external-work-claude-md.md` no longer describes `--add-dir` as OS-level, read-only, fail-closed isolation. It is a permission surface inside Claude Code: it grants read and write to the directories named and conceals nothing. Pattern A's confidentiality argument for client engagements rested on that description. The allow-list is now presented as scoping, with an operator who needs enforced confinement pointed at an OS-level boundary — a separate user account, a container, or a VM — configured before the session starts. Closes A17-2. (@2SSilver)
- 2026-09-14 — `docs/concepts.md` points at the as-built PRD set in the Leadership repo at `steward/prds/`. (@2SSilver)

- 2026-09-01 — Fixed all thirteen shipped `additionalDirectories` examples across the three repos: every one put the key at the top level of the settings JSON, where it is silently ignored — valid JSON, exit 0, no warning, and the granted directories are simply never applied. The only supported form nests it under `permissions`. Corrected the six onboarding `settings.local.json.example-<role>` files, Foundation's own `.claude/settings.local.json.example`, the five matching JSON blocks in the role onboarding markdown, and the generic example in each of the Leadership and Domain repos. The `"//"` guidance notes are unchanged. (@2SSilver)
- 2026-09-01 — Replaced the smoke test in `loading-model.md` and `setup-person.md`: it asked for a fact from `FORMATS.md`, which CI mirrors byte-identical into all three repos, so a Domain-only clone with no Foundation on disk answered it correctly and the test could never fail. The probe now reads a file under Foundation's `standards/`, which Domain and Leadership do not carry. Corrected the six sites across the three role onboarding templates — the files a joiner copies verbatim — that claimed Foundation's rules load automatically once it's a sibling repo. Fixed `external-work-claude-md.md`'s environment-variable example, which showed `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` as an alternate path-list mount; it is a boolean add-on to `--add-dir`, not a second mounting mechanism. Closes AR-04 and AR-34 on the Foundation side. (@2SSilver)
- 2026-08-26 — `docs/` added (concepts, loading model, setup-org, setup-person) and the README rebuilt as a landing page with a banner and diagrams. Every spec-section reference is gone: what an adopter needs on Day 0 is now inlined, including the branch-protection settings, and setup no longer depends on a specification that does not ship with these repos. Corrected what the harness claims about session loading — a cross-repo `@import` of a sibling's `CLAUDE.md` never inlines it, verified by test, so reach and loading are described separately and the rules that must always hold are restated locally rather than referenced. Added the `monthly-dri.yml` reusable so the monthly maintenance issue actually opens, and removed Foundation's duplicate of that issue template. `format-gate` now allows `.lycheeignore`. Closes AR-01, AR-04 and AR-07 on the Foundation side. (@2SSilver)
